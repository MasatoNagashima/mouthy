# Mouthy デモ

日本人の英語学習者向け音声英会話「Mouthy」の、ローカルで動くデモです。製品要件は [PRD.md](PRD.md) にあります。iOS アプリは将来の計画で、このリポジトリにはありません。

会話そのものは英語です。画面の説明は日本語です。

## このデモでできること

1. ロール（面接官、日常会話、出張・会議、旅行、雑談）と、話し方の目安を選ぶ
2. AI が先に話し、短い反応と質問を 1 つだけ返す
3. 考えている間は待って、長く続いたときだけヒントを出す
4. 会話を終えたあと、指摘を 1〜2 点と、詰まった表現の一覧を見る

API キーがなくても、**テキスト（モック）** で 1 から 4 まで通せます。キーがあるときだけ、ブラウザのマイクで OpenAI Realtime に接続します。

## 必要な環境

- Node.js 20 以上（このデモは Node.js 22 で起動とテストを確認しています）
- npm 10 以上
- 音声モードを使う場合は Chrome（または Chromium 系）。マイクの許可が必要です
- テキストモードの読み上げは、ブラウザの `speechSynthesis` です。Realtime API の声ではありません

## セットアップ

リポジトリのルートで実行します。

```bash
node -v
npm install
cp .env.example .env
```

`.env` は git に含まれません。キーはここにだけ書き、ブラウザのコードやコミットには置かないでください。

### API キーの取り方

1. [OpenAI の API keys](https://platform.openai.com/api-keys) を開く
2. 秘密鍵を作成する（`sk-` で始まります）
3. `.env` の `OPENAI_API_KEY=` の右に貼る
4. すでに `npm run dev` を起動している場合は、一度止めてから起動し直す

キーを空のままにすると、画面に「`OPENAI_API_KEY` が必要」と出ます。その状態でも「テキストで試す」は使えます。

モデル名は 2026-10-28 時点の公式ドキュメントに合わせ、環境変数で差し替えます。

| 変数 | 既定値 | 意味 |
|---|---|---|
| `VOICE_PROVIDER` | `openai` | `gemini` にすると、このデモのブラウザ音声は始まりません |
| `OPENAI_API_KEY` | 空 | サーバーだけが使う秘密鍵 |
| `OPENAI_REALTIME_MODEL` | `gpt-realtime-2.1` | Realtime のモデル名 |
| `OPENAI_TRANSCRIBE_MODEL` | `gpt-4o-mini-transcribe` | 学習者の字幕用モデル。`gpt-4o-transcribe` も増分字幕に使える |
| `OPENAI_VOICE` | `marin` | 読み上げ声。`cedar` も公式の推奨です |
| `GEMINI_API_KEY` | 空 | 補助アダプタ用。ブラウザ音声には使いません |
| `GEMINI_LIVE_MODEL` | `gemini-3.8-live` | Gemini Live のモデル名 |
| `PORT` | `8787` | トークン発行サーバーのポート |

`gpt-realtime-2.1` と `gemini-3.8-live` は、PRD の「gpt-realtime-2.1」「Gemini 3.8 Live」に対応する、確認できた公式のモデル名です。名前が変わったら `.env` だけを変えてください。

## 起動

開発モード（画面とトークンサーバーを同時に起動します）:

```bash
npm run dev
```

ブラウザで <http://127.0.0.1:5173> を開きます。API は同じオリジンの `/api` 経由で、`127.0.0.1:8787` にプロキシされます。待受はローカルだけです。

本番と同じ形で、ビルド済みの画面をトークンサーバーから配信する場合:

```bash
npm run build
npm start
```

このときは <http://127.0.0.1:8787> を開きます。`.env` は起動時に読まれます。

止めるときは、起動したターミナルで Ctrl+C を押します。

## 使い方

### テキスト（モック）

キーは不要です。

1. ロールを選ぶ。必要なら「今日のゴール」と「追加の役割指示」を書き換える
2. 「間とヒントの設定」で、ヒントまでの秒数を変えられる（5〜30 秒、既定 12 秒）
3. 「テキストで試す」を押す
4. 英語で返す。詰まったら `um` や日本語のままでも送れる
5. 送らずに待っていると、設定した秒数のあとでヒントが 1 つ出る。同じ沈黙のあいだは繰り返さない。話したあとに再び黙ると、上限まで次のヒントが出る。入力中はヒントは出ない
6. 「会話を終えて振り返る」を押す
7. フィードバックが 1〜2 点、詰まった表現の一覧が出る。表現はこのブラウザに保存され、次の開始時の質問に入る

「ブラウザの読み上げ」にチェックがあると、モックの英文をブラウザが読み上げます。チェックを外すと文字だけです。

### 音声

1. `.env` に `OPENAI_API_KEY` を入れてサーバーを再起動する
2. 画面の案内が「音声の準備ができています」になることを確認する
3. 音声の送信についての説明にチェックを入れる
4. 「音声で話す」を押し、Chrome のマイク許可を出す
5. AI が先に話す。下の「いまの発話」に、話している途中の字幕が出ます。言い終わると上の「会話」に残ります
6. 考えている間は黙っていてよい。`um` や言いよどみでは、semantic VAD の `eagerness: low` が最大約 8 秒待つ
7. こちらが全く話さない状態が続くと、画面の待ち時間のあとでヒント用の応答が 1 回出る（1 セッション最大回数まで）
8. 終わったら「会話を終えて振り返る」

音声の画面は、終わった発話の履歴と、いま話している 1〜2 行の字幕に分かれます。AI の字幕は `response.output_audio_transcript.delta` を順に足します。学習者の字幕は `conversation.item.input_audio_transcription.delta` を足し、`completed` で確定文に置き換えます。確定前の文字は薄い表示で、振り返りの指摘と詰まった表現には使いません。

学習者の行は `input_audio_buffer.speech_started` の時点で作り、文字起こしが遅れても返答の後ろに回りません。`conversation.item.added` の `previous_item_id` と `input_audio_buffer.committed` でも位置を合わせます。聞き取れなかった行は「聞き取れませんでした」と残し、空の吹き出しのままにはしません。

公式の Realtime 文字起こしガイドでは、`gpt-4o-mini-transcribe` と `gpt-4o-transcribe` の delta は増分です。`whisper-1` の delta は、そのターンの全文です。既定は増分が出る `gpt-4o-mini-transcribe` で、`OPENAI_TRANSCRIBE_MODEL` で変えられます。同じガイドでは、入力の delta はサーバーがターンを確定したあと（VAD の commit 後）に届きます。話している最中の字幕は「話しています…」で、部分的な文字はその後に流れます。

テキストモードでは、入力中の文が「いまの発話」に確定文として出ます。送ると履歴に移ります。

音声モードは、この環境に API キーがなかったため、実マイクでの字幕の流れは未確認です。接続に失敗したときは、モデル名とキーの権限を確認し、テキストモードで流れだけ見てください。

## なぜ OpenAI Realtime を本命にしたか

PRD は Gemini 3.8 Live と gpt-realtime-2.1 の両方を候補にしています。このデモのブラウザ音声は OpenAI Realtime だけを実装しました。

- ブラウザでは WebRTC がマイク、再生、エコーキャンセルを受け持てる。Gemini Live は WebSocket と PCM の自前処理が必要で、ブラウザでは壊れやすい
- ターンの制御は `semantic_vad` の `eagerness: low` が使える。公式の説明では、`uhhm` のように言い切っていない音声をターンの終わりと見なさず、low は最大約 8 秒待つ。PRD が問題にしている「少しの沈黙で割り込む」に対して、意味で待てる
- Gemini の `silenceDurationMs` は無音の固定タイマーで、公式の推奨は 500〜800ms。PRD の 1000〜1500ms は未検証の提案で、固定タイマーは考え中の間を切りやすい
- PRD でも gpt-realtime 側は「制御・安定性優先」の候補になっている

長い秘密鍵はサーバーにだけ置きます。ブラウザは `POST /v1/realtime/client_secrets` で発行した短命トークン（`ek_...`）だけを受け取り、`POST /v1/realtime/calls` で WebRTC 接続します。公式のブラウザ手順と同じです。音声の中身は、このデモのサーバーを経由しません。

Gemini は `POST /api/providers/gemini/token` で短命トークンを発行する補助アダプタだけです。`silenceDurationMs` と低い発話終了感度をトークンの制約に入れます。ブラウザの全二重音声にはつながっていません。

## 実装した範囲（PRD の P0）

| PRD の P0 | デモでの対応 |
|---|---|
| 会話主導エンジン | システムプロンプトとモックが、毎ターン短い反応 + 質問 1 つ。AI が先に話す。ゴールと追加指示を開始前に変えられる |
| ターンテイキング制御 | 既定は `semantic_vad` / `eagerness: low`。`server_vad` を選ぶと `silence_duration_ms` を 800〜2000（既定 1200）で API に渡す。入力中・発話中はヒントを出さない |
| 相づち | 待ちが 2 秒を超えると画面に `Mm-hmm.`。入力中・発話中も画面に短い相づち。モデルの発話は相づちで始める。スピーカーから相づちを重ねると、マイクが拾ってターンを切るので、発話中の声の相づちは入れていない |
| ヒント | 完全な沈黙が続いたときだけ。既定 12 秒、最短 5 秒。同じ沈黙では 1 回で、学習者が話したあとに再び黙ると上限まで（1〜5 回、既定 3）。モックは決まった文、音声モードは同じ制約を付けた `response.create` |
| 日本語サポート | プロンプトで、責めずに英語の言い方を 1 つ示して続ける。モックも同じ。日本語の発話は詰まりとして残す |
| ロール / シナリオ | 面接官、日常会話、出張・会議、旅行。ユースケースにある雑談も、同じテンプレートで選べる。指示文は開始前に確認できる |

P0 の受け入れ条件のうち、デモで機械的に守っているもの:

- モックの各ターンは質問が 1 つ。評価語（score、間違い、点数など）を会話中に出さない
- 考え中の沈黙では応答を始めない。ヒントは設定時間のあとだけ
- 前回このブラウザで詰まった表現を、次のセッションの指示と最初の質問に入れる

## 入れていないもの、既知の制限

P1 以降で、デモに含めていないものです。

- 自動のレベル判定。開始前の手動選択だけ（初級は速度 0.9、上級は 1.05）
- 発音の音響フィードバック。PRD でも実現方法は未決で、音素採点は非目標。振り返りは文字からの文法・表現で、最大 2 点
- アカウント、サーバーへの学習履歴、訂正履歴、発音プロファイル、セッション要約
- 進捗の可視化（P2）
- 利用分数の上限、キャッシュ命中率の監視、費用アラート
- API 障害時の自動切り替え。プロバイダの差し替え口だけ
- Gemini のブラウザ音声、15 分での再接続、iOS / Android
- 法務レビュー済みの同意。デモでは保存しないことと、OpenAI に音声が送られることの説明とチェックだけ

そのほか、確認できていないことです。

- **ライブの音声会話は未検証です。** この作業環境に API キーがなく、マイクでの割り込み率、日本語混在の認識、実遅延は測っていません
- 質問を 1 つに保つ制約は、プロンプトとモックでは強制しています。Realtime のモデルが毎回守るかは未検証です
- `semantic_vad` では `silence_duration_ms` は効きません（公式仕様）。無音のミリ秒は `server_vad` のときだけ送ります
- 全く話していないときのヒントは、クライアントのタイマーです。発話の途中の間は API の VAD に任せます。`idle_timeout_ms` は「無音が異常」という電話向けなので使っていません
- ライブ音声の字幕は未検証です。文字起こしは別モデルで、モデルが聞いた内容とずれることがあります（公式の注意どおり）。入力の途中字幕は、ターン確定後の delta に依存します
- ターンの取り方（semantic VAD、`eagerness: low`、`create_response: true`）はこの変更では変えていません。考え中に AI が話し始める挙動は残っています
- 相づちの「声」は、応答ターンの冒頭だけです。待っている間と発話中の相づちは画面表示です
- 詰まった表現の保存先は `localStorage` だけです。ブラウザのデータを消すと消えます
